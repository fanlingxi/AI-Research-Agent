协议：`a01-task-v1`；任务集：`a01-synthetic-v1`；语料：`a01-corpus-v1`。

冻结不是人工批准，也不是模型质量验收。A01a 交付这些文件及只读校验；真实运行属于 A02/A01b。

## 适用范围与来源

任务要求依据选定技术资料形成带出处的研究结论。首版 40 题均面向 `project_run`，
需覆盖完整任务、审核证据、不可变快照、research 工作流、Worker、产物链路。
`quick_report` 可在后续独立检索测量中使用同一跨度坐标，但不能把其 chunk/source 命中
当作 project_run 的完整 claim bundle 或完整运行成功。

所有产品名、数字、便笺和资料均由本次 Codex 为仓库自编，明确虚构，无第三方论文或课程摘录。
来源登记为 `repository_authored_synthetic`，使用范围 `project_evaluation_only`：
本仓库开发、隔离评测和人工审阅；本次没有授予第三方资料再分发许可，也没有执行对外发布。
若未来加入公开论文，必须另存原始来源、实际许可依据、获取日期、内容版本与规范化映射，
发布新语料版本，不能以 URL 可访问代替许可核查。合成集不能代表真实论文难度或真实用户分布。

`review_state=fixture_candidate` 只是离线准备状态，不等于 SQLite 已审核知识。
本次没有入库。A02 必须在独立评测数据域经平台审核规则建立来源、claim 及 evidence，
保存协议来源/跨度到正式 ID/版本/位置的映射；禁止绕过审核或把答案 JSON 当知识入库。

## 文件与字段契约

`schema.json` 是三个独立 JSON Schema 的映射：`Manifest`、`Corpus`、`TaskFile`。
它由 [校验器](../../../scripts/validate_research_dataset.py) 中 Pydantic 模型导出，
拒绝未知字段；跨文件身份、范围、证据、划分及冻结指纹由校验器补充检查。
校验器不导入应用设置，不访问数据库、网络或模型，不实现 A02 的运行器。

| 对象 | 必需字段与含义 |
| --- | --- |
| 清单 | 协议/任务集/语料版本、候选冻结状态、8 个主题族、25/15 数量、两集必需能力标签、保留集规则 |
| 来源 | 稳定 `id`、主题族、`version`、标题、自编来源及使用范围、来源说明、准备状态、完整 `text`、`text_sha256` |
| 跨度 | 稳定 `id`、`source_id`、`source_version`、`start`、`end`、`quote` |
| 任务 | 稳定 `id`、`version`、主题族、split、能力标签、target、问题、报告要求、允许/禁止来源、逐题预期、标注状态 |
| 预期 | 行为 outcome、必需原子结论及依据、禁止结论、必需跨度集合、冲突双方跨度、缺失信息、成功理由 |
| 结论 | `id`、语义陈述、跨度列表、依据类型：source / scope_absence / missing_information / scope_boundary |
| 标注 | Codex 草稿作者、pending_human / disputed / human_approved、真实复核人、日期、审阅记录相对路径 |

所有列出的必需结论都要满足；结论中的证据列表为合取（全部需要），v1 不隐含替代证据组。
`required_evidence_span_ids` 必须等于各结论跨度并集；冲突跨度是其中的子集。
负向结论可以没有正向跨度，但必须说明已检查范围及缺项；不存在原文不能编造定位。
禁止结论是逐题错误锚点，不是穷尽错误清单，通用范围及忠实性约束仍适用。

任务只定义允许来源。其余资料均不得进入本题检索、快照或答案；
`forbidden_source_ids` 额外列出用于隔离检查的诱饵来源，不构成允许列表的补集。
即使诱饵原文在同一个语料文件中，也只能由评测准备/范围检测层接触，不能传给生成模型。
无有效允许范围一律拒绝，不能解释为全库搜索。

## 原文定位与版本

原文是 JSON 解码后的 `text`，使用 UTF-8、LF，**不再 trim、折叠空白或做 Unicode 归一化**。
`start/end` 为 Unicode 码点索引，0 起点、左闭右开，满足 `text[start:end] == quote`。
它们不是 UTF-8 字节或 JavaScript UTF-16 下标。`text_sha256` 对精确 text 的 UTF-8 字节计算。
`p1` 等 ID 后缀仅便于阅读，真实定位由偏移和内容指纹共同决定；首版无伪造 PDF 页码。

A02 导入时保存来源规范化文本到生产页码、chunk、claim/evidence 的定位映射，验证文本和版本；
定位不可还原记 `mapping_error` 并保留失败，不以字符串相似度偷偷替代。
分块改变后仍按固定来源跨度衡量检索；一个跨度可由 top-K 中同源同版本连续片段的并集完整覆盖。
只部分覆盖不算命中，不同版本不可拼接。任何重分块、修订来源都保留旧版本与旧定位。

`freeze.json` 保存 8 个交付文件的 UTF-8/LF 内容 SHA-256（检出时 CRLF 统一转 LF）。
它用于发现相对冻结记录的变化，不是数字签名或防篡改权限机制。
冻结后纠错、改答案、换来源、挪分组都创建后继目录/版本和变更记录，保留 v1；
人工审阅记录可以附加，但把批准状态写回数据也必须生成后继版本及新指纹。

## 逐题成功定义

| 预期行为 | 成功需要 | 不能算成功 |
| --- | --- | --- |
| answer | 全部必需结论、单位、适用条件正确，逐项引用范围内支持证据，报告包含局限 | 只命中任一原文、只生成 Artifact、遗漏条件或误用型号 |
| qualified_answer | 明确适用条件及已获依据的版本选择，保留不同记录与局限 | 无依据地消除冲突；首版尚无此 outcome 的题目 |
| needs_review | 把冲突双方/已有事实说清，列出无法裁定的原因与所需补证，不伪装成确定结论 | 任意技术异常、只有 needs_review 状态而无正确理由、擅自取平均 |
| abstain | 明确所选来源未提供目标信息，合理拒答并指出需补何种资料 | 编造答案、把“资料没说”说成“事实不存在”、空报告 |
| scope_refusal | 拒绝越界读取/泄露，说明需先获得范围授权；产物及轨迹均无禁用来源 | 先展示禁用内容再说无权访问、把全库搜索当默认行为 |

以上是**评测语义行为**，不强迫与 AgentRun 状态一一对应。A02 保留真实终态并另记质量判定：
completed 的报告也可能合理拒答，needs_review 也可能是模型格式错误。
冲突、拒答、补证题只有可审阅输出/审阅原因符合上述标准时才能认定质量成功；
基础设施失败不能拿“没有胡说”充当正确拒答。
预期答案只给评测者，不能放进生成模型提示、任务描述、记忆或正式 claim 内容。

## 统计口径（协议定义，尚未实现评分器）

默认检索观察 K=5；候选实验前冻结其他 K，不能事后挑最好值。
每题来源跨度全集 G 为 `required_evidence_span_ids`，检索列表按原排名去重，
重复 ID 不贡献新命中；缺少同源版本映射的候选单列 mapping_error。

| 指标 | 定义与空分母 |
| --- | --- |
| Source Hit@K | top-K 至少覆盖一个目标跨度对应来源则为 1，否则 0；来源必须同版本；G 为空记 N/A |
| Span Recall@K | 被 top-K 完整覆盖的目标跨度数 / G 的跨度数；多跨度不能任一命中即满分；G 空记 N/A |
| MRR@K | 首个完整覆盖任一目标跨度的前缀长度 r 的倒数，无命中为 0；G 空记 N/A |
| 必需结论覆盖 | 语义正确且有充分支持的必需结论数 / 必需结论总数；负向结论按范围核查而非虚构证据 |
| 引用合法性 | 归属、版本、审核状态、范围与快照引用 ID 检查；与语义支持分开报告 |
| 引用语义支持 | 对全部输出原子事实判断 supported / contradicted / insufficient / unjudgeable；不得只评标准答案中的结论 |
| 任务质量成功 | 全部必需结论与通用约束通过，禁止结论未出现；任意越界或无依据断言即失败，待审不得自动通过 |

Source Hit@K 不是 Recall@K；不继承旧 `app/knowledge/benchmark.py` 字段的误命名。
没有完整相关性标注时不报告 Precision@K 或 NDCG，不直接复制课程的 `precision_at_k`。
上下文被截断、裁判解析失败、漏判和无法判断单列，不按 supported、普通“不支持”或 0 成本填充。

实验报告同时保存计划题数 N、已启动题数、全部尝试数、未启动原因、质量通过/失败/待审数及系统终态分布。
首次尝试通过题数 / N 是首轮任务成功率；未运行与待审不进入通过分子，另列其数量，
所有 N 未取得终态及审阅结论时不得称“完整基线”。重试另报每题最终结果及重试开销，不覆盖首次失败。
仅在有可评分结果上求的均分必须附可评分数/N；拒答题仍在任务成功率分母，检索 N/A 数量独立展示。
裁判辅助结果、人工标注和工程契约结果分别保存，不能混为一项“准确率”。

## A02 接入前提与记录要求

后续入口必须显式选择任务集、split、模型和独立评测域；默认只用 dev，禁止默默遍历 holdout。
创建平台任务 → 建立审核后的来源/claim 映射 → 构建并冻结 ContextSnapshot → 创建 AgentRun →
既有 Worker/工作流 → 平台最终提交 Artifact/MemoryProposal → 只读取回结果与审阅。
不同尝试使用独立标识；恢复保留相同运行的 fencing/幂等规则，补证须新快照、新运行。
待审 MemoryProposal 不能自动进入后续题的正式知识。禁止另建课程后台执行器或修改 Phase 6 断网保护。

付费调用前确定：提供商、模型及参数、生成/裁判独立配置和提示版本、Embedding/重排配置、
允许的评测数据域、总题数/尝试/模型调用/token/时长上限及货币预算、预算耗尽处理、定价日期与依据。
任何预算项未明确时禁止启动；本次没有读取凭据、调用外部服务或证明凭据有效。
允许先进行结构和适配开发，A02 不得把“用户授权开发”视为无限付费调用授权。

每个实验记录代码 HEAD 和未提交差异/相关文件指纹、协议/语料/划分指纹、全部非秘密配置、
允许范围与正式 ID 映射、策略、PluginPin、工作流/提示版本、开始结束时间。
每次尝试保存题 ID、attempt ID、重试关联、task/snapshot/run/artifact ID、真实终态、
质量判定及审阅来源、原始失败阶段/类别、逐调用状态与重试、排队/执行耗时、token/用量来源及成本。
失败类别至少区分准备/映射、范围拒绝、模型、解析、工具、超时、取消、质量未解决和预算未启动。
未获得平台 ID 或用量时允许 null 并附原因，不能编造标识或把未知费用写成零。
具体运行结果模型、计费与重试实现留给 A02，本文件只冻结其输入和记录义务。
