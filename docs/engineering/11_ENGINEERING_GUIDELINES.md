# Engineering Guidelines

## 1. 核心原则

本项目采用渐进式演进。

禁止：

-   推倒重写现有系统；
-   一次性替换全部架构；
-   为了新增功能破坏已有能力。

优先：

-   小步迁移；
-   保留兼容层；
-   增加测试；
-   使用 Migration。

------------------------------------------------------------------------

# 2. 架构边界

## Core Layer

负责：

-   数据模型；
-   基础服务；
-   状态管理。

禁止：

-   感知具体领域。

------------------------------------------------------------------------

## Knowledge Layer

负责：

-   Source；
-   Entity；
-   Claim；
-   Evidence；
-   Retrieval。

------------------------------------------------------------------------

## Memory Layer

负责：

-   Project；
-   Task；
-   Decision；
-   Artifact。

------------------------------------------------------------------------

## Agent Layer

负责：

-   Workflow；
-   Context；
-   Tool Calling。

禁止：

直接访问数据库。

------------------------------------------------------------------------

# 3. 数据原则

SQLite 是事实源。

Qdrant：

检索索引。

Neo4j：

关系投影。

Obsidian：

人工阅读投影。

任何投影都必须可重建。

------------------------------------------------------------------------

# 4. Agent 原则

Agent：

允许：

-   查询知识；
-   调用工具；
-   生成候选；
-   创建产物。

禁止：

-   直接修改正式知识；
-   自动改变项目状态；
-   自动发布 Canon。

所有修改：

Proposal

↓

Review

↓

Commit

------------------------------------------------------------------------

# 5. Code Style

要求：

-   模块化；
-   类型提示；
-   清晰接口；
-   单元测试。

避免：

-   巨型文件；
-   隐式依赖；
-   业务逻辑散落。

------------------------------------------------------------------------

# 6. Migration规范

所有 Schema 修改：

必须：

-   新 Migration 文件；
-   可重复执行；
-   有测试。

禁止：

直接修改生产 Schema。

------------------------------------------------------------------------

# 7. Testing

每次修改需要验证：

## Existing Tests

保证旧功能。

## Migration Tests

保证数据迁移。

## New Feature Tests

保证新增能力。
