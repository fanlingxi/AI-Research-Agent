# Repository Analysis Template

## 目标

在任何代码修改前，让 Codex 先理解现有项目。

------------------------------------------------------------------------

# 1. 项目结构分析

记录：

-   根目录；
-   Python模块；
-   API；
-   数据库；
-   测试目录。

输出：

目录树。

------------------------------------------------------------------------

# 2. 技术栈分析

检查：

-   Python版本；
-   Framework；
-   Database；
-   Vector DB；
-   Graph DB；
-   Frontend。

------------------------------------------------------------------------

# 3. 数据库分析

检查：

-   当前Schema版本；
-   Migration；
-   表结构；
-   数据关系。

重点：

识别：

-   Knowledge相关表；
-   Review相关表；
-   Report相关表。

------------------------------------------------------------------------

# 4. 当前业务流程

梳理：

## Ingestion

文件如何进入系统。

## Extraction

如何产生候选知识。

## Review

如何审核。

## Projection

如何生成：

-   Neo4j；
-   Obsidian。

------------------------------------------------------------------------

# 5. 技术债分析

检查：

-   强耦合模块；
-   重复逻辑；
-   缺少抽象的位置。

------------------------------------------------------------------------

# 6. Migration建议

输出：

保留：

新增：

替换：

废弃：

------------------------------------------------------------------------

# 7. 修改风险评估

每个修改：

标记：

Low

High

# 8. 修改前必须回答的问题

1.  当前模块作用是什么？

2.  未来架构中属于哪一层？

3.  是否影响旧数据？

4.  是否需要 Migration？

5.  如何测试？
