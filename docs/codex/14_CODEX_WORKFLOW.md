# CODEX_WORKFLOW

## 1. 文档读取顺序

Codex 开始任何修改前，必须依次阅读：

1.  CODEX_MASTER_PROMPT.md
2.  PROJECT_SPEC.md
3.  MIGRATION_PLAN.md
4.  ENGINEERING_GUIDELINES.md
5.  当前阶段对应 Prompt

禁止跳过架构文档直接修改代码。

------------------------------------------------------------------------

# 2. 工作模式

采用：

Analysis → Plan → Implement → Test → Report

## Analysis

先分析：

-   当前代码结构；
-   相关模块；
-   数据流；
-   潜在风险。

输出：

-   修改范围；
-   影响文件；
-   数据迁移风险。

------------------------------------------------------------------------

## Plan

执行修改前：

明确：

-   修改目标；
-   实现方案；
-   测试方案。

大型修改需要拆分。

------------------------------------------------------------------------

## Implement

要求：

-   小步修改；
-   保留兼容；
-   避免无关重构。

------------------------------------------------------------------------

## Test

每次修改后：

必须运行：

-   单元测试；
-   Migration测试；
-   关键流程测试。

------------------------------------------------------------------------

## Report

每次任务结束输出：

    Changes:
    - 修改内容

    Files:
    - 修改文件列表

    Migration:
    - 数据影响

    Tests:
    - 测试结果

    Next:
    - 下一步建议

------------------------------------------------------------------------

# 3. 修改原则

## 不允许

-   删除已有功能；
-   未分析直接重构；
-   修改无关模块；
-   引入大量无必要依赖。

------------------------------------------------------------------------

# 4. 架构约束

必须保持：

SQLite: 事实源

Qdrant: 检索索引

Neo4j: 关系投影

Obsidian: 人工阅读投影

------------------------------------------------------------------------

# 5. Agent开发原则

Agent：

可以：

-   查询；
-   分析；
-   生成候选；
-   创建Artifact。

Agent禁止：

-   直接修改正式知识；
-   绕过Review；
-   自动修改长期Memory。

------------------------------------------------------------------------

# 6. 代码质量要求

新增代码：

需要：

-   类型提示；
-   清晰接口；
-   测试；
-   文档。

避免：

-   巨型函数；
-   隐式状态；
-   循环依赖。
